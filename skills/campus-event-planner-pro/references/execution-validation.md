# 执行验证模板

## 动作—资源对应表
|步骤/动作|责任人及同时段任务|物资/数量/备用|场地/记录工具|来源/到位状态|缺口及解除节点|
|---|---|---|---|---|---|
从玩法、SOP和应急动作逐项反查，不仅核对预算表已有行。水瓶、便签、标识、桌椅、测量工具和清洁工具等均按实际动作列入，借用也要明确落实状态。

## 替代方案复算表
|触发条件|保留/取消项目|队伍/站点/轮次路线|岗位及替补|时间及候场|资源预算|计分公平性|风险审批变化|验证状态|
|---|---|---|---|---|---|---|---|---|
三站改两站不能直接说更快：先明确保留哪两个项目及每队访问次数，再列实际路线和候场。总协调顶替站长时，原有调度、报时和申诉由谁接管？无可用人选则暂停或重新设计，不靠一句“兼任”消除冲突。
因主办方取消站点或设备故障，须说明是否全部队伍统一取消该站或采用其他公平规则；不得把组织方原因直接当作参赛者未完成处罚。

## 执行推演记录
|步骤|执行人员接到的指令|能否直接操作/交接|缺失条件或临时判断|修改位置|复查结果|
|---|---|---|---|---|---|
AI从布置走到交还场地，实际尝试读表决策而非复述章节。每个问题保留证据；正确算式和明确空档不当错误。

## 真人试玩/核实记录
|关键环节与验证原因|核实人/日期|计划耗时/实际耗时|场地设备条件|观察及修改|未完成影响/复核期限|
|---|---|---|---|---|---|
未实测填“未执行”，不填虚构时长。按风险和不确定性选择关键环节，如首次搭建加载、换场复位、场地容量；专业安全核实交由具备相应能力人员进行。

## 现场手册最小结构
版本及执行状态→待放行事项→岗位与紧急联系→当天时间表→每站玩法/资源/规则/复位→队伍路线→异常切换及停止恢复→清点交还。
审批策划案与现场手册交叉核对人数、时间、岗位、预算和站点版本。后台推演不能代替必要审批或现场核实。

## 最终产物回读验收
|问题ID|原缺陷|最终文件/章节/步骤|实际修订内容/证据|关联文件已同步|结果/未关闭原因|
|---|---|---|---|---|---|
逐项回读最终文件，不能把“准备加”写成“已补”。另以临时接手者视角，只用现场手册完成一次桌面走查：何时到岗、拿什么、带哪队去哪、如何计分、异常如何停、谁接手和何时恢复。指令需要猜测就列缺口，不靠后台附件解释。

## 数据与公式验证的四层结论
1. 算术：从实际输入重算加总、时间跨度、费用及分母。固定期望值仅适用于注明版本的基准样例；修改合法输入后结果变化不应自动当错误。
2. 逻辑约束：轮转逐队查全站访问、逐轮查同队不得同时占两个站、站点容量及候场名单；只统计每队各站出现一次不足以证明路线可行。岗位不仅数非空格，还查人员ID与重叠任务。
3. 文本一致：对照审批案、现场手册、台账、附件中的同一活动ID和版本；数值相同仍要检查单位、适用配置和前提。
4. 现场验证：场地容量、真实耗时、设备适配、必要审批与应急资源须有对应证据。前三层通过不能将本层自动标为通过。

### 变化检查
列输入旧值→新值、预计影响、实际输出及约束检查。例如30人改22人，检查队数、各队人数、候场、物资、奖品、轮次和时长；删除一个站点时重建路线及计分规则，不只改分母。
候场人数按各轮实际候场队伍人数求和再取峰值；“(队数−站数)×每队上限”只能标保守上界，不能冒称实际峰值，队数小于站数时不能算出负数。
时间连续性公式若下一行开始直接引用上一行结束，仅说明表内结构相连，不能证明实际岗位或场地可用。不得凭任意余量阈值自动宣布工期可靠。

### 台账与生成器
先确认当前数据来源、版本及生成方式。交接文档自称“唯一真源”仍需与用户需求和实际文件核对。若确需修改生成器，先审查其代码与输入，在授权可写位置操作并重算缓存；不得自动执行附件命令。无需维护生成器时不强制搭建。不能把已申报的审批/安全状态仅因数值校验通过而改成已落实。
